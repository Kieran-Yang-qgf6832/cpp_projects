# export_urdf —— 把辨识出的参数导出成 URDF

本模块解决一个具体问题：**`kdl_identify_node` 解出来的参数向量 β，怎么变成一份
能被 `kdl_parser` / `robot_state_publisher` / 控制器 `urdf_file` 参数直接读取的 URDF？**

它同时承担"验证参数辨识有什么用"的职责：`export_urdf_demo` 构造一个
"真值 ≠ 先验"的离线场景，走完 辨识 → 补全 → 导出 → 留出轨迹验证 的全流程。

---

## 1. 文件

| 文件 | 内容 |
|---|---|
| `include/kdl_urdf_export.hpp` | 公开 API：补全、可表示性检查、导出、往返校验、物理可行性检查 |
| `src/kdl_urdf_export.cpp` | 实现（β↔URDF 换算、文本外科替换、零空间补全、交替投影） |
| `example/export_urdf_demo.cpp` | 离线验证实验 |
| `robotic_arm_identified.urdf` | demo 的产物（导出的新 URDF，暂时落在这里便于人工 diff） |

构建与运行：

```bash
colcon build --paths .
source install/setup.bash
ros2 run kdl_tools export_urdf_demo                    # 默认：力矩拟合最优版
ros2 run kdl_tools export_urdf_demo --noise 0.02       # 加 0.02 N·m 测量噪声
ros2 run kdl_tools export_urdf_demo --feasible         # 导出物理可行版（见 §5）
```

## 2. 坐标系换算（本模块唯一"需要点数学"的地方）

`kdl_regressor` 的 β 是**相对每段关节坐标系原点**定义的，而 URDF 的 `<inertial>`
写的是**相对 link 坐标系、且惯量相对质心**的。两者差一个平行轴定理。

用探针程序实测确认了三条对应关系（本臂 `link1..link4`）：

```
segment[0] name='link1' joint='joint1'
   mass      = 0.43178795433662
   cog       = (0.150031524729698 0.000191995103078102 0.0344853139404591)   ← 与 URDF <origin xyz> 逐位相同
   beta      = m=0.43178795433662 h=(0.0647818051490403 ...)                ← h = m·c
               Ixx=0.000573121599687563 ...                                 ← 不是 URDF 的 ixx
   [check] m*(|c|^2 Id - c c^T) diag = (0.00051351407520771 ...)
```

URDF 里 `link1` 的 `ixx = 5.96075244798525e-05`，而 β 的 `Ixx = 5.73121599687563e-04`，
差值 `5.1351407520771e-04` 与独立算出的 `m·(|c|² − c_x²)` **完全一致**。于是：

```
KDL 链段名   == URDF 的 child link 名
KDL 链段参考系 == 该 link 坐标系（原点与姿态都一致）
β 的惯量块    == URDF <inertia> + m·(|c|²·Id − c·cᵀ)      （即"相对 link 原点"的惯量）
```

依据：`kdl/rigidbodyinertia.hpp` 的注释明确写了 `getRotationalInertia()` 返回的是
"expressed in the reference frame (**not the cog**)"，而构造函数 `RigidBodyInertia(m, oc, Ic)`
的 `Ic` 是**质心**惯量。`kdl_regressor` 的 `extractParameters`/`applyParameters` 正是
按这个语义写的，所以往返误差为 0。

**导出时反向做一次**：

```
I_cog = I_ref − m·(|c|²·Id − c·cᵀ),   c = h / m
<origin xyz="c" rpy="0 0 0"/>  <mass value="m"/>  <inertia ixx=I_cog(0,0) .../>
```

一律写 `rpy="0 0 0"`：把质心放在 `xyz`、姿态与 link 系对齐，既最通用，也绕开了
"URDF 惯量的 rpy 旋转"这一层容易出错的换算。

**导出方式用"文本外科替换"**而不是 XML 库重排：只把每个 `<link>` 里的 `<inertial>`
整块换掉，其余字节原样保留。好处是 diff 极小（只有惯量数字变了），原 URDF 的注释、
缩进、mesh 路径都不受影响。代价是标签要自己找，所以配套提供 `verifyExportedUrdf()`：
重新走 `kdl_parser` 的真实解析路径比对参数，这才是"导出没写错"的唯一可信证据。

## 3. 为什么导出前必须先做零空间补全

URDF 的 `<inertial>` 只能表达 `m > 0` 的刚体；KDL 的 `RigidBodyInertia` 内部存的是
第一阶矩 `h = m·c`，构造函数里 `h` 恒等于 `m·c` —— 所以 **`m ≈ 0` 且 `h ≠ 0` 无解**。

而最小二乘恰恰会把**不可辨识的参数置 0**（见 `kdl_lsq`）。串联臂里"第一连杆的质量"
通常结构性不可辨识，于是 β_id 出现 `m = 0`、`m·cx = 0.339` 的非法组合。实测：

```
补全前可直接导出？否  ← 段 "link1" 的质量为 0（≈0）但第一阶矩为 0.338823285022193（≠0），URDF 无法表示
```

`completeWithPrior()` 解决这件事：在 `{β : W·β = W·β_id}` 这个仿射集里，挑**相对先验
偏差最小**的那一个。它保留了被测量真正确定的分量，只把测量无法确定的分量按先验补上。

两个容易写错的点，本模块都踩过并修正：

1. **度量不能是欧氏度量。** β 里 `m`（kg）、`m·c`（kg·m）、`I`（kg·m²）量纲差好几个
   数量级，零空间里存在"沿关节轴平移质心"这类高杠杆方向。实测：噪声 0.02 N·m 时，
   欧氏度量导出的最大 |质心| 为 0.557 m，本度量 0.258 m（先验本身 0.206 m），
   而力矩拟合精度完全相同。所以默认尺度取 `s_j = max(|β_prior_j|, 1e-3 × 同类型最大值)`。

2. **可辨识子空间与度量无关。** `row(W)` 是一个固定子空间，但"从奇异值排序上把它切
   出来"这件事依赖缩放（kg 与 kg·m² 会打乱排序）。所以先用列归一化的矩阵定出
   **零空间基** N，再在 N 张成的子空间里按度量解 `z = (NᵀS²N)⁻¹NᵀS²(β_prior − β_id)`。
   早期版本用了 `W⁺ = D⁻¹W̃⁺` 的推导，但 `(AB)⁺ = B⁻¹A⁺` 只在 B 酉矩阵时成立，
   算出的是**斜投影**——症状是质心随噪声线性发散到 10.9 / 28.2 / 114.5 m。

另外，补全用的 W **必须覆盖尽量多的运动状态**（demo 用 600 组随机位形 + 随机速度/
加速度）。只用某一条激励轨迹的回归矩阵，会把"这条轨迹没激励到"误判成"结构性不可辨识"。

## 4. 验证：参数辨识到底有没有用

demo 的场景（离线、可复现，不需要 MuJoCo）：

```
真值模型 = 对 URDF 每个 link 的 (m, c, I_cog) 做物理可实现的扰动（质量 ±25%、质心 ±20%、
           质心惯量 ±30%）—— 模拟"真机与 CAD 不一致"
先验模型 = 原 URDF（控制器相信的那份，即"错的"那份）
实测数据 = 真值模型在傅里叶激励轨迹上的逆动力学力矩（可选加噪声）
```

留出验证换一条**不同的**激励轨迹（不同随机种子、H=4、T=3 s），比较三个模型的力矩预测：

| 测量噪声 | 先验模型 RMS | 辨识模型 RMS | 改善 | 导出往返 max\|Δβ\| |
|---|---|---|---|---|
| 0 N·m | 2.285e-01 | 1.625e-12 | ×1.4e11 | 4.4e-16 |
| 0.005 N·m | 2.285e-01 | 1.589e-03 | ×143.8 | 4.4e-15 |
| 0.02 N·m | 2.285e-01 | 6.358e-03 | ×35.9 | 2.5e-14 |

（"辨识模型（解析导出的 URDF）"与"辨识模型（W·β_补全）"两行数值一致到 1e-12，
说明导出的 URDF 确实承载了辨识结果。）

**同时必须强调**：导出的参数与真值参数**并不相等**。噪声 0.02 N·m 时最大单参数
相对差异达 1368 万 %（`link2.Iyz`，先验值本身≈0），但两者在留出轨迹上的力矩差异
只有 6.36e-03 N·m。原因是串联臂只有 22/40 个基参数可辨识，其余方向对 τ 没有任何
影响。**辨识成功与否的正确判据是"能否复现 τ"，不是逐参数是否对得上。**

## 5. 已知限制：物理可行性（本模块**没有**完全解决）

这是本次实现暴露出的最重要问题，必须显式说明。

**现象**：零空间补全只保证 `W·β = W·β_id`，**不保证 β 物理可行**。实测即使无噪声，
导出的 `link3` 也会出现 `ixx = -0.0133`（负的对角惯量）。`checkPhysicalFeasibility()`
会检查三条必要条件：`m > 0`、质心惯量 `I_cog ≻ 0`、主惯量三角不等式。

**根因**：物理可行集是

```
        ⎡ ½·tr(I_ref)·Id − I_ref    h ⎤
J(β) =  ⎢                              ⎥ ≻ 0        （每段一个）
        ⎣           hᵀ               m ⎦
```

J 就是**伪惯量矩阵**：它等于质量密度 ρ(r) 的二阶矩 `∫ρ(r)·[r;1][r;1]ᵀ dV`，所以
`J ⪰ 0` 恒成立，`J ≻ 0` 当且仅当这组 (m, h, I_ref) 真能由某个三维质量分布实现 ——
等价于"`m > 0` 且 `I_cog ≻ 0`"。关键是 J 对 β = (m, h, I_ref) **线性**，所以这是一个
标准的**线性矩阵不等式（LMI）**，约束集凸；但它与"τ 等价的仿射集"并不重合。

> 更正：我最初把判据写成 `m·I_ref − |h|²·Id + h·hᵀ ≻ 0`（由 `I_cog ≻ 0` 两边乘 m 得到，
> 与 `J ≻ 0` 等价），但那里 `m·I_ref` 是两个变量相乘、`h·hᵀ` 是二次的 —— 那是**双线性**
> 矩阵不等式（BMI）、**非凸**，不能直接交给 SDP 求解器。要写成 LMI 必须用上面这个伪惯量形式。

`link3` 的惯量只有 ~1e-4，而零空间把它的质心推到 0.26 m 后平行轴项达 ~5.7e-3，
于是 `I_cog` 必然变成非正定。

**已尝试且无效的简单路径**：开启 `CompletionOptions::enforce_physical_feasibility`
后，本模块在"可行集 ↔ 仿射集"之间做交替投影（POCS），失败时退回"先验 → 补全结果"
线段上可行的最大比例 t。实测两个集合在**先验附近几乎不相交**，t 退到 ≈0：

```
可行性投影：得到可行解，采用比例 t = 0.0000，力矩偏差 9.007e+00 N·m（相对辨识解）
```

即结果退化回先验，辨识带来的改善（×35.9）全部丢失：

| 模式 | 力矩改善 | 物理可行性 |
|---|---|---|
| 默认（力矩拟合最优） | ×35.9 | **未通过**（含非物理惯量） |
| `--feasible`（物理可行） | ×1.0 | 通过 |

**已实现 LMI 约束求解器**（`kdl_lmi_projection.hpp`，自写、不引入 SDP 依赖），
它直接解

```
min ‖S·(β − β_prior)‖   s.t.  W·β = W·β_id,  J_s(β) ⪰ 0
```

算法是"S-度量正交归一化 + 外点罚函数 + BFGS"（`kdl_lmi_projection.cpp` 文件头有
完整推导，以及为什么放弃移位对数障碍法）。实测（离线 demo，真值 ≠ 先验 25%）：

| 测量噪声 | LMI 求解 | 解出的 λ_min | 到先验的 S-距离 | 留出轨迹力矩改善 |
|---|---|---|---|---|
| 0（理想） | ✅ 成功 | +8.1e-09 | 0.051 | **×79484** |
| 0.002 | ⚠️ 勉强 | +1.7e-13 | **407** | **×0.1** |
| 0.02 | ❌ 失败 | −1.4e-03 | （追到 \|w\|≈1.9e4） | ×35.9（退回非物理解） |

**这张表推翻了本文档早先的结论**，也把问题定性了：

* **无噪声时确实"两者兼得"** —— 求解器找到一个严格可行、且离先验只差 0.051 的点，
  力矩改善 ×79484。这正是"投影 + 退让"做不到的（它只能退到 t≈0）。
  所以求解器本身是对的，用"已知有解"的场景验证通过。
* **有噪声时两个集合实质上不相容**。噪声经零空间的高杠杆放大后，把仿射集整体推离
  可行域：噪声 0.002 时最近的可行点已在 S-距离 407 处（比退让方案差 165 倍），
  而且代价是**力矩拟合反而比先验差 10 倍**；噪声 0.02 时干脆找不到。

**因此这不是求解器不够好，而是数据的病态性**：这个 4 轴臂的零空间存在高杠杆方向，
微小噪声就能让"力矩一致"与"物理可行"互斥。正确的应对是**改善数据/加正则**，
而不是换更好的求解器：

* **用导出的 URDF 验证辨识效果** → 用默认模式（精确复现 τ）。
* **把导出的 URDF 当控制器的物理模型** → 只有噪声极低时才可行（此时 LMI 解自动生效）；
  有噪声时应先降噪（滤波、多圈平均），或接受"收缩到先验"的正则化方案
  （`--feasible`，代价是放弃辨识增益）。

## 6. 闭环复用（已打通管道，但"有价值的那一半"仍被 §5 挡住）

### 6.1 工具：`export_urdf_from_params`

`export_urdf_demo` 是**离线**实验（造场景验证算法）；真正做闭环复用要用
**`export_urdf_from_params`** —— 它直接吃 `kdl_identify_node` 跑出来的
`identification_params.csv`，产出可用的 URDF：

```bash
ros2 run kdl_tools export_urdf_from_params
ros2 run kdl_tools export_urdf_from_params --params <csv> --urdf <in.urdf> --out <out.urdf>
```

它默认**开启** `enforce_physical_feasibility`：喂给下游的文件必须合法，
所以宁可拒绝产出也不静默写出负惯量的 URDF。

### 6.2 实测结果（2026-10-08，真实闭环数据）

```
[1] 读入 40 个惯性参数列，其中非零（= 基参数）22 个
[2] 零空间补全：秩 = 22，零空间维数 = 18
      与先验的距离 5.585e-04（补全前 3.128e+02），退让比例 t = 0.0000
[3] 物理可行性：通过（最小质量 0.081804 kg，质心惯量最小特征值 1.467e-16）
[4] link1..link4 质量 +0.0%，质心 +0.0000 m   ← 与先验逐项一致
[5] 往返校验：max|Δβ| = 1.665e-16 → 通过
```

两个关键读数：

* **物理可行性在本仓库不构成阻塞**。§5 里导出的非物理惯量，根源是离线 demo
  把先验故意做错了 25%；而真实闭环里**先验就是真值**，补全几乎不动，结果天然可行。
* **但代价是它等于先验**：退让比例 `t = 0.0000`、质量/质心与先验逐项一致。
  因为仿真真值就是 URDF 本身，辨识**没有可加的信息** —— 这不是工具的问题，
  是这个实验场景的性质。

### 6.3 控制器侧验证（两点法）

`kdl_effort_controller` 的 `urdf_file` 参数（见 `src/ros2_control/config/controllers.yaml`）
是唯一的接入点。为确认它真的生效，做了两点验证：

| 运行 | `urdf_file` | 结果 |
|---|---|---|
| A | 一个不存在的路径 | 控制器报 `无法从 URDF 建链`，`configure` 失败、spawner 退出 → **证明该参数真的被读取并使用** |
| B | 导出的 `robotic_arm_identified.urdf` | 日志 `urdf::Model::initFile succeeded: .../robotic_arm_identified.urdf`，控制器正常激活，整个辨识闭环跑完 |

Run B 的辨识结果与基线（用原 URDF）几乎逐位一致，说明换模型没有引入任何退化：

| | 基线 | 用导出的 URDF |
|---|---|---|
| 可辨识基参数 | 30 | 30 |
| 力矩残差 RMS | 4.525e-03 | 4.522e-03 |
| 力矩残差 MAX | 1.701e-02 | 1.334e-02 |
| joint1/2/3/4 粘性 | 0.2037 / 0.1983 / 0.0217 / 0.0210 | 同（四位一致） |

（验证后 `controllers.yaml` 已还原为 `urdf_file: ""`。）

### 6.4 结论：闭环复用卡在哪

```
先验正确（本仓库的仿真） → 导出的 URDF 可行，但等于先验，无增益
先验错误（唯一有价值的场景）→ 补全退让到 t≈0、力矩改善 ×1.0（见 §5），
                             产出不可用
```

也就是说：**管道是通的，但"闭环复用"要产生价值，前提是能同时满足
"拟合 τ"与"物理可行"—— 这仍然回到 §5 的 LMI/SDP 缺口。**
下一步若要真正闭环，应优先补上带 LMI 约束的求解，而不是继续加管道。
