# 启动指南

本仓库有四块内容，启动方式各不相同，先看这张速查表：

| 想干什么 | 一条命令 |
|---|---|
| 快速验证算法层（不需要仿真） | `ros2 run kdl_tools control_demo` |
| 起 MuJoCo 仿真 + 力矩控制器 | `ros2 launch kdl_tools arm_mujoco_control.launch.py` |
| **发任务让机械臂运动**（仿真 + 控制器 + 解算节点） | `ros2 launch kdl_tools arm_mujoco_control_with_bridge.launch.py` |
| 同上但无界面（ssh / CI） | 后面加 `headless:=true` |
| 让机械臂走到目标关节角 | 见 §3.3（`/control_task` service） |

四块内容分别是：

* **KDL 教学库**：`src/{Tools,Kinematics,Dynamics,Interpolation}` —— URDF 建链、正逆运动学、动力学、插值。
* **任务层**：`src/control` —— 把「任务」翻译成关节空间轨迹；对外是一个节点（`kdl_control_node`）。
* **控制环内控制器**：`src/ros2_control/src/kdl_effort_controller.cpp` —— 前馈 τ_ff + PID 反馈的**力矩控制器**。
* **仿真接入层**：`src/ros2_control` —— 把 MuJoCo 当成 ros2_control 的一块硬件。

> **当前是力矩控制链路**（已不再是 JTC 位置伺服）：
> `调用者 ──srv /control_task──▶ kdl_control_node ──topic /control_reference──▶ kdl_effort_controller ──effort 接口──▶ MuJoCo <motor>`
> 设计与踩坑记录见 `src/ros2_control/PLAN_TORQUE.md` 与 `src/ros2_control/力矩控制问题报告.md`。

## 1. 环境与构建

```bash
source /opt/ros/jazzy/setup.bash
cd ~/MyProjects/cpp_projects/kdl          # 包根就是工作区根
colcon build --paths .
source install/setup.bash
```

要点：

* **`--paths .` 只构建本包 `kdl_tools`**。`src/mujoco_ros2_control/` 是上游源码，
  默认不用管 —— `/opt/ros/jazzy` 里已经装了同系列的二进制包。
  若要连那份源码一起编译，去掉 `--paths .`，并且**先 `source install/setup.bash` 再 build**，
  否则容易链接到 `/opt` 里的旧版本。
* **改完 `src/model/`、`src/control/`、`src/ros2_control/` 里的任何文件都要重新 `colcon build`**：
  URDF/MJCF/YAML/launch 都是靠安装规则拷到 `share/kdl_tools/` 之后才生效的。
* 力矩控制器是插件，改了 `.cpp` 后也要重建（`add_library(kdl_effort_controller SHARED ...)`）。
* 环境里有 CycloneDDS，**忘了 `source /opt/ros/jazzy/setup.bash` 会报找不到 `libddsc.so.0`**。

## 2. 最短启动路径（TL;DR）

```bash
source /opt/ros/jazzy/setup.bash
cd ~/MyProjects/cpp_projects/kdl && source install/setup.bash

# 终端 1：起仿真 + 控制器 + 解算节点（约 10 s 内就绪）
ros2 launch kdl_tools arm_mujoco_control_with_bridge.launch.py headless:=true

# 终端 2：关节空间任务，8 s 走到目标
ros2 service call /control_task kdl_tools/srv/ControlTask \
  "{task_type: 0, goal_joint: [0.5, -0.4, 0.6, 0.3, 0.2, 0.5], duration: 8.0}"
```

返回 `error_code=0, success=true` 即到位。

## 3. 力矩控制主力流程

### 3.1 两个 launch 的区别

| launch | 拉起什么 |
|---|---|
| `arm_mujoco_control.launch.py` | `robot_state_publisher` → `ros2_control_node`（MJCF + 物理线程）→ `spawner(joint_state_broadcaster, kdl_effort_controller)` → 可选 `rviz2`。**不含解算节点**。 |
| `arm_mujoco_control_with_bridge.launch.py` | 上面全部 + **`kdl_control_node`**（托管 `/control_task`，发 `/control_reference`）。**要发任务就用这个。** |

只想起仿真、自己再单独起解算节点时：

```bash
ros2 launch kdl_tools arm_mujoco_control.launch.py headless:=true
ros2 run kdl_tools kdl_control_node          # 另开终端
```

启动参数（两个 launch 同名同默认值）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `headless` | `false` | `true` = 不开图形窗口 |
| `sim_speed_factor` | `1.0` | 仿真时间/墙钟倍数；`5.0` = 5 倍速跑。>0 时会锁住 MuJoCo 窗口里的实时率滑块 |
| `rviz` | `false` | 额外启动 RViz2（看 TF 与机器人模型） |
| `mujoco_model` | 空 | 留空 = 用 `share/kdl_tools/model/scene_torque.xml`（力矩版 MJCF） |

> ⚠️ **已知现象（问题 3）**：控制器被 spawner 激活之前，`effort` 命令一直是 0，
> 机械臂会在重力下**自由下落约 0.5 s**，最后锁在"摔到哪算哪"的位形。
> 这是当前未根治的结构性问题，详见《力矩控制问题报告》§3。
> 观察方法见 §3.4。

### 3.2 确认起来了

```bash
ros2 control list_controllers
#   joint_state_broadcaster  joint_state_broadcaster/JointStateBroadcaster  active
#   kdl_effort_controller    kdl_tools/KdlEffortController                  active

ros2 topic hz /clock                       # ≈ 500 Hz = 1/timestep（物理步 2 ms）
ros2 topic echo /joint_states --field position --once
ros2 topic list | grep -E "control_reference|status"
```

### 3.3 发任务（`/control_task` service）

service 类型 `kdl_tools/srv/ControlTask`，**阻塞式**：轨迹跑完（或超时/失败）才返回。

**方式 A：关节空间任务**（`task_type: 0`）

```bash
ros2 service call /control_task kdl_tools/srv/ControlTask \
  "{task_type: 0, goal_joint: [0.5, -0.4, 0.6, 0.3, 0.2, 0.5], duration: 8.0}"
```

* `goal_joint`：目标关节角 [rad]，长度必须 = 6；
* `duration`：轨迹总时长 [s]；**`<= 0` 表示自动估算**（不短于 `min_duration=1 s`）。

**方式 B：笛卡尔空间任务**（`task_type: 1`）

```bash
ros2 service call /control_task kdl_tools/srv/ControlTask \
  "{task_type: 1, goal_pose: {position: {x: 0.3, y: 0.0, z: 0.4},
                              orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}, duration: 0.0}"
```

`goal_pose` 是相对 `base_link` 的末端位姿；四元数不要求归一化（节点会自己归一化）。
目标越界 / IK 不收敛 / 接近奇异会返回 `error_code=3`。

**返回码**（`ControlTask.srv` 注释里也有）：

| error_code | 含义 |
|---|---|
| `0` | 成功（轨迹跑完且终点残差在 `tracking_tolerance` 内） |
| `1` | 还没收到 `/joint_states`，无法确定当前状态 |
| `2` | 请求不合法（`task_type` / `duration` / `goal_joint` 长度） |
| `3` | 解算失败（目标越界、IK 不收敛、接近奇异……见 `message`） |
| `4` | 参数/配置错误 |
| `5` | 控制器未接手轨迹（`kdl_effort_controller` 没激活？关节名不匹配？） |
| `6` | 等待执行结果超时 |
| `7` | 已有任务在执行（不支持排队/取消） |
| `8` | 轨迹时间跑完但**终点未到位**（残差超阈值；常见于自碰撞卡住或力矩被限幅） |

### 3.4 观察运行情况

```bash
# 参考轨迹（控制节点发出的控制点：position/velocity/effort）
ros2 topic echo /control_reference --once

# 控制器的执行状态（active / progress / error_code）
ros2 topic echo /kdl_effort_controller/status --once

# 实际施加的力矩与关节状态（硬件接口自身发布，不受广播器频率限制）
ros2 topic echo /mujoco_actuators_states sensor_msgs/msg/JointState
```

**观察问题 3（激活前自由下落）**：先把采样挂上，再启动（必须先起 echo，且**带类型**，
否则话题未发布前推不出类型）：

```bash
# 终端 A
ros2 topic echo /mujoco_actuators_states sensor_msgs/msg/JointState
# 终端 B
ros2 launch kdl_tools arm_mujoco_control.launch.py headless:=true
```
启动后约 0.55 s 内 `effort` 恒为 0（无控制），之后才被控制器接管。

### 3.5 暂停 / 单步 / 复位（调试用）

```bash
ros2 service call /mujoco_ros2_control_node/set_pause \
  mujoco_ros2_control_msgs/srv/SetPause "{paused: true}"

ros2 service call /mujoco_ros2_control_node/step_simulation \
  mujoco_ros2_control_msgs/srv/StepSimulation "{steps: 10}"      # 单步 10 个物理步

ros2 service call /mujoco_ros2_control_node/reset_world \
  mujoco_ros2_control_msgs/srv/ResetWorld "{keyframe: ''}"
```

> 服务的节点名随版本可能不同，`ros2 service list | grep set_pause` 确认一下即可。

### 3.6 停止

在 launch 的终端按 **Ctrl-C**（`ros2 launch` 会把 SIGINT 转给所有子节点，正常退出）。
后台启动的要按进程优雅终止，别 `kill -9`：

```bash
pkill -INT -f "arm_mujoco_control"
```

## 4. 关节与执行器约定（下发前先看这张表）

来自 `src/model/robotic_arm.urdf`，也是 `robotic_arm_torque.xml` 里的 `<motor ctrlrange>`：

| 关节 | 行程 [rad] | 执行器 | 力矩上限 [N·m] |
|---|---|---|---|
| `joint1` | −3.14 ~ 3.14 | `<motor name="motor1">` | ±50 |
| `joint2` | −1.57 ~ 1.57 | `motor2` | ±50 |
| `joint3` | −2.80 ~ 2.80 | `motor3` | ±50 |
| `joint4` | −1.82 ~ 1.92 | `motor4` | ±100 |
| `joint5` | **−0.40 ~ 0.40** | `motor5` | ±50 |
| `joint6` | −3.14 ~ 3.14 | `motor6` | ±50 |

* 执行器是 **`<motor>` 纯力矩**，`ctrl` 的语义就是关节力矩 [N·m]（`gear=1`，插件不做缩放）。
  对应的 `ros2_control` 命令接口是 `effort`，由 `kdl_effort_controller` 写。
* ⚠️ **`<position>` 与 `<motor>` 是编译期二选一、不能运行时切换**：effort 命令接口对
  `<position>`/`<velocity>` 执行器会**直接报错并跳过**（关节收不到任何力矩）。
  位置伺服版模型是 `src/model/robotic_arm.xml` + `scene.xml`，仍保留可回退。
* **PID 增益来源**：`src/ros2_control/config/mujoco_pids.yaml` 的
  `pid_gains.position.<joint>`（`p/i/d/u_clamp/i_clamp`）。这组值是按实测等效惯量
  `M(q)` 用 `kp=Mωn², kd=2ζMωn`（ωn=15, ζ=1）整定的，**不是**随手填的经验值；
  换机型必须重算（见《力矩控制问题报告》§2）。
* **自碰撞**：连杆碰撞用的是外形网格，MuJoCo 对非凸网格用凸包近似，会误报接触。
  `robotic_arm_torque.xml` 里已把**非相邻连杆两两 `<exclude>`**；若要真实自碰撞，需补简化碰撞几何。
* 关节角**零位是「直臂」奇异位形**（雅可比最小奇异值 ≈ 0.0011）。直接下发关节角没问题，
  但 `src/control` 的**笛卡尔任务**不要以零位为起点/目标（逐点逆解会不连续）。

## 6. 仿真链路的两个关键参数（改之前先读）

| 项目 | 位置 | 当前值 |
|---|---|---|
| 物理步长 | `src/model/scene_torque.xml` 的 `<option timestep>` | 2 ms（`/clock` 实测 ≈ 500 Hz） |
| 控制周期 | `src/ros2_control/config/controllers.yaml` 的 `controller_manager.update_rate` | **500 Hz（2 ms）** |
| 每控制周期物理步数 | 两者之比 | **1** |

**必须保持整数比**：`/clock` 只在物理步边界跳变，控制环是睡在仿真时钟上的
（`use_sim_time=true`），比例不是整数时唤醒时刻会被量化到下一个步边界，实际控制周期会变长。
力矩环取 500 Hz（= 物理步速率）是为了让相位滞后最小、稳定裕度最大。
`sim_speed_factor` 只改仿真时间/墙钟比，**不改变**这个比例。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `failed to load shared library libddsc.so.0` | 忘了 `source /opt/ros/jazzy/setup.bash` |
| 改了 URDF/MJCF/YAML/launch 没反应 | 忘了 `colcon build --paths .`（文件要先装到 `share/kdl_tools/`） |
| `MuJoCo model file ... does not exist!` | `mujoco_model` 路径不对；默认应指向 `share/kdl_tools/model/scene_torque.xml` |
| 起完就报 `Effort command interface ... not supported with position or velocity actuator. Skipping it.` | 用了位置版 MJCF（`<position>`）。力矩模式必须用 `scene_torque.xml`（`<motor>`） |
| 启动后机械臂不是从零位开始，而是"摔"到一个位形 | **问题 3**：控制器激活前有 ~0.5 s 无控制自由下落。见《力矩控制问题报告》§3 |
| 机械臂大幅摆动 / 力矩长期饱和 | PID 增益与 `u_clamp` 不匹配（线性区太窄）。见《力矩控制问题报告》§2 |
| 某个关节怎么都到不了目标（时间跑完却差一截） | 多半是连杆自碰撞卡住（返回 `error_code=8`）。见《力矩控制问题报告》§4 |
| `Joint ... is not supported with motor or custom actuator without defining the PIDs` | 同名子串也出现在位置接口路径上；本方案用 effort 接口，不受影响 |
| 手臂在零位附近自己抖 | 相邻连杆凸包接触；已在 MJCF 的 `<contact><exclude>` 里排除相邻对（并额外排除了非相邻对） |
| `Could not enable FIFO RT scheduling policy` | 普通用户没 RT 权限，仿真场景忽略即可 |
| 想跑得比墙钟快 | `sim_speed_factor:=5.0`（控制周期与步长的关系不变） |
